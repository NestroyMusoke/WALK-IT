# Decision and gate log

## 2 November 2026: tracker scale investigation

The user-directed investigation supersedes the previous assumption that a single tracker scale could be used. Five private captures show 3.95 times spread between two author walks and 4.03 times among three approximately 10 m screening runs. A repeatable global scale fails. Within-session constant, stepped and drifting scale remain unidentifiable without marked positions. See `docs/SCALE_AUDIT.md`. The existing captures remain development and validation material, not held-out visitor trials.

The instrumentation card records the exact `configure()` and `updateCameraProjectionMatrix()` argument objects and call times, the engine version when provided by `onAttach`, per-frame tracking status, world-point count and median forward depth, and timestamped device-motion values. World points were enabled using the documented `enableWorldPoints` option. DeviceMotion permission is requested in the camera-start tap as required by the browser API. The three-second sway is an instructed interval, not proof that the user moved; logged motion permits later inspection. Mark taps record tracker pose at 0, 2, 4, 6, 8 and 10 m. There has been no new phone trial of this instrumentation.

For local alignment, retain the older full 3D Umeyama function and add a recent gravity-aligned yaw/scale/translation hypothesis. The new function uses only recent pairs and rejects insufficient or inconsistent inliers; it never sets metric scale or navigation readiness. A further failed-first fixture showed it could accept a transform supported only by old pairs, so the newest two pairs must also be inliers. The synthetic straight-path/outlier, recent-scale-change and mirror tests pass. For planar anchors, use OpenCV 5 `SOLVEPNP_IPPE` after planar homography RANSAC, compare both returned solutions, and abstain when they are similarly plausible. Replace the hull-only coverage decision with the 10th-to-90th percentile spread on both image axes. The development fixture's narrow patch had spread 0.1048; the threshold was set to 0.12 in config so that fixture still abstains. These are synthetic tests, not a field-tuned accuracy claim. OpenCV 5.0.0 was import-tested; the IPPE two-solution behavior is documented in OpenCV 5's official PnP reference.

The gate is predeclared before any new 20 m field run: at least four correct fresh starts out of five, each within the existing 1.0 m plus measured position uncertainty and 10-degree heading rule, zero accepted wrong starts, and route-end error strictly below 3 m in at least half of the runs. The reference route length is 20 m. Unknown metric scale, heading, reference uncertainty or missing attempts keeps the gate open. No field data for this gate exists yet. Do not choose native platform or labelled replay without the user's decision if the gate fails.
